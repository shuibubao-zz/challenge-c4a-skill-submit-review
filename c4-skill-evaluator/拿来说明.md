## 一、拿了什么

### 1. 官方 starter：`c4a-skill-evaluator-starter`（必拿，挑战资料自带）

| 拿的东西 | 具体 |
|---|---|
| 技能定位与触发词 | "扫描文件夹 → 识别作者 → 评完整性 + 质量 → 出报告"这个任务定义 |
| 完整性 5 槽位 | Skill 说明文档 / 可执行内容 / Demo / 教学说明 / AI 生成日志 |
| 质量四条件 | reusable / executable / verifiable / clear_io 这**四个维度的名字** |
| 综合分公式 | `完整性 × 0.4 + 质量 × 0.6`（v1 原样保留） |
| 双输出形态 | Markdown 报告 + Excel 详表 |

**没拿的**：v1 的质量维度只有"信号词列表"（命中即算过，无取证），
v2 把它整体换成了"检测项 + 证据锚点"结构。

### 2. 基座技能：`wechat-doc-mapper`

| 拿的东西 | 具体 |
|---|---|
| 工作流骨架 | 扫描 → 识别作者（三级回退）→ 完整性表 → Markdown + Excel 双输出 |
| 报告组织方式 | "总览 → 每人详情 → 缺口统计 → 改进建议"这一叙述顺序 |

**代码层面**：按函数名比对 `c4_evaluator.py`(v3 时 1176 行，v4 加固后 1304 行) 与 `wechat_doc_mapper.py`(556 行)，
**同名函数只有 `main`** —— 骨架与思路沿用，实现是重写的。
upstream 的文档解析（`_title_from_pdf/docx/pptx/...`）与挑战映射（`map_to_challenges`）**一条都没用**。

## 二、改了什么（我的部分）

### 改法 1：每条判定必须带证据锚点（最大的一处改动）

v1：关键词命中 → ✅。v2：**命中 + 指得出在哪一行**。
输出形如 `SKILL.md:78`（正例）或 `未发现：C:\Users\, /Users/...`（反例）。

**为什么**：评审的价值不是打分，是**可复核**。被评审者看到"你没有安装说明"时，得能当场查证。

### 改法 2：三项"真实校验"，不靠关键词

| 检测项 | 怎么验 |
|---|---|
| 代码能否通过语法校验 | **真的跑 `py_compile`** |
| `.skill` 包结构是否完整 | **真的当 zip 打开，检查有无 SKILL.md** |
| Demo 是不是真实产物 | **真的读字节数 + 判空/判占位** |

YAML 里标 `real: true`，**缺证据即判 fail**。

### 改法 3：负信号硬地板 + 反堆砌

- 硬编码本机路径 / 明文密钥 / `TODO`/`YOUR_XXX` 占位符 → 该条件**封顶**，
  正面信号命中再多也不放行（`apply_negative_cap`）。
- 同一关键词反复出现**不累计**加分（`anti_gaming.duplicate_content`）。

### 改法 4：给评审器自己配了测试

- `--self-test`：16 项断言（含端到端全流程、无 PyYAML 解析回归、2 项结构形态用例）；
- `build_golden_set.py` + `golden_test.py`：**8 个人工标注 fixture** 测评审器自身误判率。

### 改法 5：零强制依赖

有 PyYAML 就优先用 PyYAML，没有则降级到内置 mini-YAML 解析器（含引号感知的行内注释剥离）；
`openpyxl` 降级为**可选**。
（v4 教训：rubric 里写行内注释曾把 mini 解析器击穿——`int('2 # R1…')` 直接崩。
"零强制"不是"两条路径天然等价"，等价性必须有自检兜底，见改法 4 第 2、3 项。）

### 改法 6：修掉的自身缺陷（均来自实测/外部复核）

| 缺陷 | 现象 | 修法 |
|---|---|---|
| `YOUR_` 大小写不敏感 | `your_file.py` 被判占位符 | 正则 + `case_sensitive` |
| `evaluate_quality` 未传 `details` | 证据锚点丢一半 | 补签 |
| `real: true` 未实现"缺证即 fail" | 真实校验形同虚设 | 补 `REAL_CHECKS` 路由 |
| YAML 中文引号嵌套 | 自检直接失败 | 改 `label` 引号 |
| 质量评级未过负信号地板 | 有硬编码路径仍判 ✅ | 接上 `apply_negative_cap` |
| **行内注释击穿 mini 解析器（v4，外部复核发现）** | 无 PyYAML 环境 `int('2 # R1…')` 崩溃，自检/golden 全挂 | 引号感知的注释剥离 + 数值兜底 + 自检真检查 |
| mini 解析器转义与 PyYAML 不一致（v4） | `\\n`、`\\\\`、内联列表 `\"` 两环境行为不同 | 顺序转义还原 + 自检深度比对 |

## 三、没拿什么

- **没用** wechat-doc-mapper 的文档解析（PDF/Word/PPT/LaTeX）——C4A 不需要按挑战归类。
- **没用**任何 LLM API——评审器是**确定性**的，同输入永远同输出，可复现可审计。这是刻意选择。
- **没有**把评分标准硬编码——全在 `references/c4_rubric_v2.yaml`。

---

## 四、一句话总结

**拿的是任务定义、五个槽位、四个维度名、综合分公式和报告骨架；
我加的是证据锚点、三项真实执行校验、负信号硬地板 + 反堆砌、
给评审器自己配测试（16 项自检 + 8 例黄金集）、零强制依赖。**
