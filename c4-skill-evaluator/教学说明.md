# 教学说明：怎么用 c4-skill-evaluator

> 面向第一次用的人，跟着走一遍约 5 分钟。
> 目标：你会用它评审一个装着 C4 技能提交的文件夹，并且**看得懂它为什么这么判**。

---

## 0. 先确认环境

```bash
python --version          # 3.9+ 即可
python scripts/c4_evaluator.py selftest
```

自检 16 项必须**全 PASS**（v4 起含"无 PyYAML 环境解析回归"与 2 项结构形态用例）。它检查的例如：

- "无硬编码路径"能真的识别出 `C:\Users\xxx\...`
- `py_compile` 对一段坏代码返回 False
- 反堆砌：同一关键词抄 20 遍不会比抄 1 遍分高
- 端到端：造假作者跑完整流程能出分

**自检不过就别用它评审别人。**

---

## 1. 准备输入

一个本地文件夹，里面是大家交的技能。**命名规范不是必需的**：

```
1) 文件名里的「姓名_C4_xxx」  → 置信度 high
2) 父目录名                   → 置信度 mid
3) 都认不出 → "Unknown"       → 置信度 low（报告会标"需人工确认"）
```

⚠️ 识别不出时它**不猜**，标 `low` 让你人工补。

---

## 2. 跑评审

```bash
python scripts/c4_evaluator.py evaluate "C:/群文件/C4_提交" \
    --out ./评审输出 --json ./评审输出/result.json
```

`--rubric` 不写就用默认 `references/c4_rubric_v2.yaml`；不写 `--json` 也行，Markdown 一定有。

---

## 3. 看报告（按这个顺序读）

### 第一块：班级总览

看三件事——**多少人齐**、**最常见缺什么**、**最弱维度**。
"最常见缺失：Demo（×7）"意味着全班通病，值得群里统一提醒，而不是挨个私聊。

### 第二块：每位作者

**完整性表**：注意"判定方式"列——

| 判定方式 | 含义 | 怎么用 |
|---|---|---|
| `content(6 signals)` | 靠内容信号命中 | 可信度高 |
| `filename` | 只有文件名像，内容没匹配上 | ⚠️ 人工看一眼，可能是空壳文件 |

**质量表**：**看"依据"列，而不是看评级**。依据是证据锚点：
`SKILL.md:78`（在第 78 行找到）或 `未发现：C:\Users\, /Users/, ...`（该找的都找了，没有）。

**这就是本评审器和"关键词打分脚本"的区别**：被评审者不服时，你可以把这一行直接指给他看。

### 第三块：改进建议

按丢分从大到小，是**可执行动作**（"补 Demo""删掉硬编码的 C:\Users\ 路径"），不是套话。

---

## 4. 想改评分标准：改 YAML，不要改代码

```yaml
quality:
  reusable:
    check_items:
      - id: no_hardcoded_path
        label: "无硬编码本机绝对路径"
        none_of: ["C:\\\\Users\\\\", "/Users/", "/home/"]
```

- `any_of`：命中任一即算过
- `none_of`：命中任一即判不过（负信号）
- `real: true`：这一项**真的去执行**，缺证据即 fail
- `case_sensitive`：区分大小写（`YOUR_` 那条必须区分，否则 `your_file.py` 会被误判）

改完跑 `selftest` 和 `golden_test.py`，看误判率有没有变差。

---

## 5. 它测不了什么（别拿它当裁判）

| 它能测 | 它测不了 |
|---|---|
| 文件齐不齐 | 这个技能有没有用 |
| 有没有硬编码路径/密钥 | 思路新不新颖 |
| 代码能不能过语法 | 代码逻辑对不对 |
| Demo 是不是空文件 | 教学效果好不好 |
| 输入输出说没说清 | 作者是不是真理解了 |

**它是助教，不是考官。** 把可机械核验的部分做扎实，把需要人的判断明明白白留给人。

---

## 6. 这个评审器自己的准确率（实测）

跑 `python scripts/golden_test.py`：

```
完整性判定（n=40）       97.5% 准确
质量评级（n=32）         精确匹配 59.4% ｜ 相差≤1级 96.9%
严重误判（✅↔❌ 颠倒）    3.1%
作者识别                 8/8
```

⚠️ **精确匹配不到 60% 是故意的**——测试集里放了边界样本。
如果打满 100%，只有两种可能：测试集太简单，或标签是照着输出填的（循环论证）。
真正要盯的是**严重误判率**。
