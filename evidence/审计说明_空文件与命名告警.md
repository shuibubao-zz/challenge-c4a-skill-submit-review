# 审计说明：空文件与命名告警（不是交付物缺失）

> 提交前体检报告（`evidence/submit_guard_audit.txt`）会报两类红线。
> **它们都是黄金测试集里的"故意为之"，不是交付物缺失。** 评审如见告警请先读本文件。

---

## 1. 6 个"空文件"——全部来自 `G07_empty_files` fixture

```
c4-skill-evaluator/references/golden_set/G07_empty_files/周八_C4_AI日志.md       (0 字节)
c4-skill-evaluator/references/golden_set/G07_empty_files/周八_C4_demo.png        (0 字节)
c4-skill-evaluator/references/golden_set/G07_empty_files/周八_C4_skill说明.md    (0 字节)
c4-skill-evaluator/references/golden_set/G07_empty_files/周八_C4_tool.py         (0 字节)
c4-skill-evaluator/references/golden_set/G07_empty_files/周八_C4_教学说明.md     (0 字节)
```

**为什么必须存在**：这个 fixture 的用途就是测评审器"能不能识别出交了空文件充数的人"。
如果这些文件不是空的，这个测试就失效了。

**对应的护栏**：评审器的"Demo 为真实产物（非占位/空文件）"检测项会真的读字节数；
黄金集里这个 fixture 的期望标注是 ❌，评审器确实判了 ❌（见 `evidence/golden_test_v3.txt`）。

## 2. 命名告警：fixture 里写作 `C4` 而不是 `C4A`

```
张三_C4_AI日志.md  ← 挑战号写作 C4
```

**这是对的，不是笔误**：本评审器评审的对象就是**C4 技能提交**，
所以测试用的假提交必须命名为 `_C4_` 才能被 `NAMING_RE` 识别。
如果改成 `_C4A_`，作者识别正则反而匹配不上，黄金集会失效。

---

## 3. 命名不规范的文件（41 个）

包括 `README.md`、`_starter/**`、`_upstream/**`、`c4-skill-evaluator/**` 内部文件。

- `_starter/`（官方 starter）与 `_upstream/`（基座技能）是**参考资料**，不进自己的 GitHub 仓库；
- `c4-skill-evaluator/` 是技能包本体，其内部文件按**技能包约定**命名（`SKILL.md` / `scripts/` / `references/`），
  不套用 `姓名_挑战号_部件` 的提交命名规范；
- 交付文档（4 份 `卢怡然_C4A_*.md`）**全部**符合命名规范。
